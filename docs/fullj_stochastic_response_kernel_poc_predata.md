# Full-J stochastic broadband response-kernel POC — pre-data declaration

## Purpose

The nested K0->K1 and K1->K2 scalar tagged-radial campaigns established a robust broadband tagged response but failed smooth scalar radial interpolation at late time. K1->K2 improved transfer and power error at every redshift, while direct late-time response retained sharp sign-changing radial structure and failed the preregistered spike veto.

This milestone does not attempt K3/K4 scalar densification. It measures the **full symmetric finite-difference Fourier response column** generated by selected input tags on frozen Gaussian broadband backgrounds:

`K(k_out,k_in,z | G) = [W_hat(+epsilon)-W_hat(-epsilon)]/(epsilon A_in) * exp(-i phi_in)`.

The diagonal element `k_out=k_in` must reproduce the already locked scalar tagged response. Off-diagonal elements quantify mode coupling generated by the nonlinear broadband state.

A technical PASS means that this kernel diagnostic is finite, constraint-clean, tangent-stable, resolution-stable and regresses to the locked scalar diagonal. The physics decision (diagonal reduction sufficient versus mode-coupling kernel required) is reported separately and is not itself a PASS/FAIL criterion.

## Physics decision thresholds

After a technical PASS, report a reduction decision using frozen thresholds:

`STOCHASTIC_SCALAR_DIAGONAL_REDUCTION_SUPPORTED=True` only if all three are true:

- maximum bounded off-diagonal energy fraction across all primary `(G,k_in,z)` <= `0.05`,
- maximum out-of-band leakage fraction across all primary `(G,k_in,z)` <= `0.05`,
- maximum B2->B4 relative L2 difference of the full bounded kernel columns <= `0.10`.

If the technical diagnostic passes but any of these conditions fails, set

`STOCHASTIC_MODE_COUPLING_KERNEL_REQUIRED=True`

and keep the scalar-reduction flag false.

These are interpretation flags, not technical gate manipulation.

## Scope

- a continuous stochastic radial scalar transfer,

- LOS lensing,
- ACT likelihood,
- observational claims.
